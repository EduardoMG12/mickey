# 0010 — Releases: one Linux tarball built for glibc 2.35, an NSIS installer for Windows; GPL-3.0-or-later

- **Status:** Accepted
- **Date:** 2026-09-28 (license, initial commit `3ba3745`); 2026-10-21
  (installers, PR #81); 2026-10-23 (Linux build in Ubuntu 22.04, #220,
  PR #223)

## Context

Mickey has to install on the owner's PCs and, once public, on anyone's,
without building from source. Two facts shaped the Linux package:

- **A Linux binary needs the glibc it was built against, or newer.** Built
  on Arch, `mickey-ui` needed glibc 2.43 and did not start on Ubuntu 24.04
  (#220). Built on GitHub's `ubuntu-latest`, the minimum would move
  silently whenever the runner moved on.
- **What the binaries really need** is glibc 2.34 (`mickey`) and 2.35
  (`mickey-ui`, for `hypot`). Built on 24.04 they also named weak 2.39
  symbols (`pidfd_spawnp`, `pidfd_getpid` from Rust's std), and 22.04's
  loader printed a warning on every start (commit `12e6d36`).

On Windows the installer has more to do than copy files: start Mickey at
logon without a console, open the firewall on private networks only, and
install where an elevated Mickey is safe ([ADR 0009](0009-windows-administrator-mode.md)).

## Decision

- **One release workflow** (`.github/workflows/release.yml`) builds both on
  a version tag on `main`, with `Cargo.lock` (`--locked`); a tag must match
  the version in `Cargo.toml`. Each release has `SHA256SUMS`.
- **Linux: one tarball**, `mickey-linux-x86_64.tar.gz`, built **inside an
  `ubuntu:22.04` container** so the binaries name nothing above glibc 2.35.
  A step reads every version each binary names (weak ones too, with
  `objdump -T`) and fails the build above 2.35. Minimum: Ubuntu 22.04,
  Mint 21, Debian 12, Fedora 36. `install.sh` adds the user to `input`,
  installs the udev rule for `/dev/uinput`, opens the ports on firewalld or
  ufw, puts Mickey in `~/.local/bin` and starts it as a systemd user
  service; `uninstall.sh` removes it all.
- **Windows: an NSIS installer**, `Mickey-Setup-<version>.exe`, built on a
  Windows runner, installing to `$PROGRAMFILES64\Mickey`, with a firewall
  rule for `mickey.exe` on the **private** profile only, and a logon task
  made through `mickey autostart`.
- **License: GPL-3.0-or-later**, in `LICENSE` and every crate's
  `Cargo.toml`. Releases carry `THIRD-PARTY-LICENSES.txt`, generated by
  `tools/licenses/third_party_licenses.py` (commit `aeac200`).

## Alternatives considered

- **Build on the newest Ubuntu runner and state its glibc.** Tried first in
  the same PR (`ubuntu-24.04`, minimum 2.39, commit `5d1dcfb`), then
  replaced after testing Ubuntu 22.04 (commit `12e6d36`): it
  excluded Ubuntu 22.04, Mint 21 and Debian 12 for symbols that are only
  weak.
- **Distribution packages** (AUR, `.deb`, `.rpm`, Flatpak) and winget or
  Scoop. Not rejected, **deferred**: on the roadmap (#176). One tarball
  covers every glibc-2.35 distro now.
- **A statically linked (musl) Linux build.** **Not recorded**; no document
  discusses it. (Shared audio links the system's `libpulse`, so a fully
  static binary would not cover that part anyway; **inferred**.)
- **NSIS against MSI (WiX) or Inno Setup.** **Not recorded.** The docs only
  list "Windows installer" under *Packaging* in the vision; the installer
  arrived as NSIS in PR #81 without a written comparison.
- **The license.** **Not recorded.** GPL-3.0-or-later was in the very first
  commit; no document says why it was chosen over MIT/Apache-2.0. It does
  match the projects the README names as inspiration that are GPL (e.g.
  Deskflow, Input Leap, lan-mouse) (**inferred**).

## Consequences

Good:

- One Linux download works on ten tested distros and desktops (README,
  *Tested on*), and the minimum cannot drift without the build failing.
- Downloads can be checked (`sha256sum -c SHA256SUMS`); only the workflow
  builds releases (README, *Code signing policy*).
- The Windows installer puts Mickey where administrator mode is allowed.
- GPL keeps derived versions open, and the third-party notices travel with
  the binaries.

Bad, and known limits:

- **x86-64 only**, and glibc only (no musl distros like Alpine).
- **The tarball is not a package**: no updates through the distro's
  package manager.
- **Not code-signed yet**: Windows Defender may flag the installer as
  `Trojan:Win32/Bearfoos.B!ml` (README, *Known limits*); signing through
  SignPath is planned.
- **Two toolchains for Windows**: development cross-compiles with
  `x86_64-pc-windows-gnu` from Arch, while releases build natively with
  MSVC on `windows-latest`.
- **GPL limits reuse** in closed-source products (inherent to the license).
